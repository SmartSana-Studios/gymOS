# Decision Log — GymOS PRD

> Append-only. Record every decision, change, and override as it is made.

| # | Date | Decision | Rationale | Alternatives Considered |
|---|------|----------|-----------|------------------------|
| 1 | 2026-06-20 | QR check-in direction: member opens app and scans a static QR code at the gym entrance | Simpler gym-side setup (no kiosk hardware); member-initiated; matches brief's "QR check-in scanner" feature | Receptionist/kiosk scans member's phone QR — rejected: requires member to show phone to staff, slower, worse for self-service |
| 2 | 2026-06-20 | Grace period is gym-configurable (not a fixed platform value); platform default is 3 days | Different gyms have different tolerance for late renewals | Fixed 3-day platform default — retained as fallback only when gym hasn't configured |
| 3 | 2026-06-20 | Coach portal exists in V1 (assigned member list + session notes); workout plans and class scheduling remain V1.5 | User confirmed coach portal should be in V1 scope; brief's V1.5 assignment overridden | Full coach portal in V1 — rejected: adds scope to a 1–2 developer, 3–4 month timeline |
| 4 | 2026-06-20 | Travel mode plan type deferred to V2.0; removed from FR-024 | Brief contained a contradiction (V1 must-have vs V2 roadmap). Travel mode implies cross-gym membership validation — a fundamentally different RLS query from the standard per-gym check-in. Adding it to V1 touches the check-in critical path with undefined logic. | Keep in V1 plan enum — rejected: creates footgun; devs would assign travel plans to members with no working cross-gym check-in logic |
| 5 | 2026-06-20 | Campay deferred to V2; V1 ships Notch Pay only behind a PaymentProvider interface | Dual-provider = 2x SDK integration, 2x webhook handlers, 2x sandbox environments, 2x error normalization for a 1–2 dev team. Abstraction costs ~2 hours and slots Campay in cleanly later. | Notch Pay + Campay both in V1 — rejected: timeline risk |
| 6 | 2026-06-20 | Offline scope limited to check-in queue only | Queuing generic "actions" is a distributed systems problem: payment initiation queued offline creates consistency risk on sync. Check-in queue only is tractable; conflict resolution rule specified (timeout backfill). | Queue all actions offline — rejected: undefined conflict resolution, payment double-submission risk |
| 7 | 2026-06-20 | Front-desk renewal flow is an inline panel (no page navigation); 3-tap maximum for straight-through cash renewal | The signature product moment needs a complete, verified interaction — not a redirect to Subscriptions page. 45-second renewal claim in UJ-2 must be achievable. | Navigate to Subscriptions page to renew — rejected: breaks the urgency of the front-desk moment |
| 8 | 2026-06-20 | Feature gating in Super Admin deferred to V1.5 pending OQ-1 resolution | Cannot ship a feature-gating control panel with no tier definitions. Active/Suspended gym status is sufficient for V1 pilot with 1–3 founder-onboarded gyms. | Include feature gating panel with placeholder tiers — rejected: ships a control with no controls |
| 9 | 2026-06-20 | Supabase region: EU West (Ireland or Frankfurt) required; US East prohibited | US East adds 200–400ms intercontinental latency on top of Cameroonian mobile network jitter; makes <3s front-desk alert NFR unachievable. Must be set before any Supabase project is created — cannot change after data is written. | US East (default) — rejected: NFR failure |
| 10 | 2026-06-20 | Language selection moved to first onboarding screen (before phone number) | UX review: a French-speaking member in Yaoundé should not see English before they've had a chance to set their language. Buried in profile settings is too late. | Language selector in profile settings only — rejected: first-impression friction |
| 11 | 2026-06-20 | JWT role claim injection (gym_id, role) via Supabase auth hook; spike required in sprint 1 | Misconfigured hook defaults to deny-all silently — a missed spike causes entire authenticated user base to be blocked. Must be verified before any RLS policy is written. | Client-side role checks only — rejected: insufficient; bypassable |
| 12 | 2026-06-20 | CSV import is all-or-nothing: all rows validated before any are inserted; first validation error aborts the entire import | Partial imports create data integrity ambiguity — some members imported, some not, with no clear recovery path. All-or-nothing with row-level error display is the correct ACID behavior. | Row-by-row with partial commit — rejected: data integrity risk |
| 13 | 2026-06-20 | Two distinct front-desk alert states: yellow grace alert (check-in accepted) vs red denied alert (check-in rejected) | UJ-2a and UJ-2b are different receptionist scenarios requiring different responses. Conflating them into one alert type obscures urgency. | Single alert type for all non-active states — rejected: obscures urgency difference |
| 14 | 2026-06-20 | Member app download handoff via SMS/WhatsApp deep link generated from the dashboard (FR-082) | The gap between "receptionist creates record" and "member opens app" was undefined. In Cameroon, where app installs feel like commitments and data costs money, this handoff is where member acquisition is won or lost. | Gym prints a generic QR for the app store — rejected: no pre-association, member may not know which app to download |
| 15 | 2026-06-20 | Goal and experience level (onboarding steps 3–4) are visible to assigned coach in coach portal | Without surfacing to the coach, goal selection is a broken promise to the member. Connecting it to the coach creates the actual value loop. | Goals for display only with no connection to any role — rejected: broken UX promise |
| 16 | 2026-06-20 | OQ-4 (travel mode V1 vs V2) resolved: V2.0 | See decision #4 above |
| 18 | 2026-06-21 | OQ-1 fully resolved: 3 default tiers named Hustle (1–30 members), Grind (31–100), Elite (>100). Same features across all tiers; member count is the only differentiator. Prices fully Super Admin configurable (no hardcoded values). Super Admin can add new tiers. | Member-count gating is simpler than feature gating and more honest about what gyms pay for (capacity). Fully configurable pricing lets GymOS adjust without code deploys. | Hardcoded prices — rejected; feature-gated tiers — rejected (same features); single flat rate — rejected (no growth path for larger gyms) |
| 19 | 2026-06-21 | Grace period platform default confirmed: 3 days (OQ-3 resolved) | Confirmed assumption; gyms can override in Settings | — |
| 20 | 2026-06-21 | Auto-timeout default changed to 8 hours (was assumed 4 hours) (OQ-5 resolved) | Gym sessions in Africa often run long; 4-hour timeout risked auto-closing active check-ins | 4 hours — rejected: too short for multi-hour training sessions |
| 21 | 2026-06-21 | Front-desk alert auto-dismiss set to 30 min default, gym-configurable (was assumed 15 min fixed) (OQ-6 resolved) | Busy front desks may miss a 15-min alert; gym-configurable gives flexibility without adding meaningful implementation complexity | 15 min fixed — rejected: too short for busy reception desks |

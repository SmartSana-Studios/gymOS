# Epic 20 Retrospective — Loyalty: Free Sessions & Free Days (V1.7)

Guests earn one free session per N paid sessions; subscribers earn R free days per K on-time renewals. Members see progress and rewards in the app, staff see the same on the member modal, and rewards are exactly-once from an append-only ledger. Loyalty is off by default per gym. Shipped as V1.7: migrations 0117-0120, dashboard from master, mobile app 1.7.

## Findings

Format: source — disposition — prevention.

### Spec-to-implementation reconciliation

- **S-1 Migration numbers shifted.** Epic context says 20.1-20.4 = 0117-0120 as-built, while `epics.md` story bodies still show 0116-0119 (`epic-20-context.md` Stories section). — *Reconcile* (action 9). Prevention: when an ad hoc migration lands mid-plan, renumber `epics.md` in the same commit.
- **S-2 Hook failure posture was left open, then decided in 20.4.** Context deferred "guard or not" (deferred-work.md l.1088-1089); `0120` header l.18-21 wraps hooks so a failure rolls back only the hook, writes `loyalty_hook_failed` audit and a `job_runs` row, and warns. The consequence is accepted but unresolved: a swallowed hook is never retried and Epic 20 forbids manual balance edits (deferred-work.md l.1100-1101). — *Defer, decide* (action 4).
- **S-3 Early renewal forfeits remaining period including rewarded free days.** `confirm_renewal` and `complete_verified_payment` start the new subscription at `current_date` (deferred-work.md l.1093); the program makes this member-visible. — *Defer, decide* (action 5). Prevention: spec the carry-over rule when a feature adds value to a period that an existing flow can discard.
- **S-4 Subscriber reward audit label not delivered.** Deferred-work.md l.1094 said "fix in 20.5"; `apps/dashboard/locales/en.json:1298` still reads "Free session granted" for `loyalty_reward_granted` and `auditLabels.ts:71-76` explicitly adds no separate label, so a subscriber's free days appear as a free session in Audit. Metadata carries `reward_days` and expiry dates. — *Fix now* (action 1). Prevention: close deferred items marked "fix in story X" when X is reviewed.
- **S-5 Refund history was never specified.** Manual QA of the 20.4 stamp reversal found staff cannot see what was refunded (deferred-work.md l.1132). Built and merged after the epic (PR #65). — *Landed.*

### Pattern divergence

- **P-1 A new cron job trips the job-runs alert until its first run.** `loyalty_sweep` (0120, 03:30 UTC) is in `scripts/job-runs-alert.sql` l.20 with a 27 h allowance, and the migration was applied the same afternoon, so the hourly workflow failed at 2026-10-14 18:38 and 22:18 UTC (GitHub runs 38616803594, 38646703770: "not running | loyalty_sweep | never"). Cleared by one manual `run_loyalty_sweep_job()` at 22:40 UTC. — *Fix now* (action 2). Prevention: add the first-run call to the stage's apply verification, not to memory.
- **P-2 pgTAP failures under load, three different files.** During this epic's local gating `auth_hook_canary`, `payments_rls_and_renewal` (28/29 ok) and `super_admin_billing_view` (plan=none) each failed once when the pgTAP stage ran concurrently with the other stages, and each passed alone (session record, `/tmp/ci-local-logs/pgtap.log`; GitHub `rls-tests` never failed). Plan=none, errors=0 points at the harness, not the SQL. Unfixed, it wears down trust in the gate and forces a manual "rerun alone" call before every merge. — *Defer, fix soon* (action 3).
- **P-3 Verify at the boundary paid off again.** The `epic20-qa` kit uses real RPCs and JWTs; it, plus manual QA with the owner, found the missing refund history, that "Expiring This Week" depends on the nightly lifecycle job (seed now runs it), and that Renew lives on the Overview table, not the member modal. All three are outside pgTAP's reach. — *Win;* Epic 19 action 10 landed for this epic.
- **P-4 Verification of staff actions before firing them.** In QA a renewal was fired for a member the owner had already renewed and had to be undone with approval. — *Accept;* prevention: check current state before any staff action in a QA run (lesson stored).

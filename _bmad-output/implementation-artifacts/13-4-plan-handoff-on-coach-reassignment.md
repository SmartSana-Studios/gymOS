# Story 13.4: Plan Handoff on Coach Reassignment

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a member whose coach has changed,
I want my existing workout plan to stay visible even though my new coach didn't write it,
so that I don't lose my program just because my coach changed.

## Acceptance Criteria

1. **Given** a coach assignment that ends (`FR-055`'s `ended_at`), **when** the member's new coach (if any) views the member's profile, **then** the previous coach's plan remains visible to the member and to Owner/Manager, but the new coach cannot edit it. [FR-111]
2. **Given** the new coach, **when** they want to make changes to the existing plan, **then** they must explicitly take ownership of it first — mirroring the V1.0 session-note handoff pattern (Story 5.1) — before any edit is permitted. [FR-111]

- **This story's actual code surface is small — most of AC #1 is already true today.** The investigation in Subtask 1.1 is the single most important thing to read before writing any code: two of the three visibility guarantees AC #1 asks for already hold with zero changes (new-coach read access, reassigned-coach's automatic loss of access). If any task in this file seems to imply a mobile change, that's a misread — flag it rather than build it.
- **The coach-name RLS gap is the same class of bug `private.is_own_coach_id()` (0041) already fixed once** — a coach has no path to read another coach's `members` row (Story 5.2's `0040` narrowing). Do not attempt to solve this with a PostgREST embed or a client-side query; it will silently return `null` for exactly the case that matters (a reassigned coach viewing the banner), the same failure mode `session_notes` already hit and fixed via a `security definer` helper.
- **Read `0080_coach_authored_workout_plans.sql` lines 189–249 (`update_workout_plan()`) before writing `take_ownership_of_workout_plan()`.** The existing `v_existing_coach_id != v_coach_id` ownership check is exactly what `take_ownership_of_workout_plan()` needs to flip — writing a *new*, subtly-different ownership rule here instead of the established one would desynchronize the two functions.
- **Decision, not left ambiguous:** Owner/Manager get the new read grant on `workout_plan_completions` too, even though AC #1's text only says "plan" — the completion badges (Story 13.3) render inline with the exercise list on the same tab, and leaving them RLS-blocked for Owner/Manager would ship a visibly half-working tab. If the user disagrees, this is a one-policy revert.
- **Decision, not left ambiguous:** the new Owner/Manager policies use exactly `['owner','manager']`, matching `manager_or_owner_read_own_session_notes`'s (0041) established role list for this same "staff oversight of coach-authored member content" class — **not** widened to include Supervisor, unlike Story 12.3's precedent. That widening was driven by an explicit mockup instruction naming Supervisor for that specific feature; no equivalent signal exists here (EXPERIENCE.md's Nav table shows *no* staff role — not even Owner/Manager — has a "Coach Portal" nav checkmark; Owner/Manager access it only via the established "sidebar hides it, RLS is the real gate" pattern already used for `/coach` and `/subscriptions`, same as this story's own new grant). Supervisor's broader exclusion from `coach_assignments`/`session_notes` visibility is a pre-existing, wider gap across several pre-Epic-9 tables — not this story's job to backfill.
- **No audit log entry for `take_ownership_of_workout_plan()`** — matches `add_session_note()`/`edit_session_note()`'s own documented reasoning (FR-080's action-type list doesn't include this action; `assign_coach()` already logs the FR-080-covered `coach_reassigned` event at the member-assignment level).
- **UX mockup exists and is authoritative here** (unlike Stories 13.2/13.3's own flagged gaps) — `EXPERIENCE.md` lines 1701–1716 specifies the exact banner copy, button label, and the "read-only until explicit take-ownership" behavior. Follow it verbatim rather than inventing new copy/flow.

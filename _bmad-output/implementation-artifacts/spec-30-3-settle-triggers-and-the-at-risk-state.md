## Intent

**Problem:** The fold and settle of 30.2 are inert: no check-in or void marks a week dirty, nothing settles on a schedule, and no member-callable function returns the open week, goal, count, settled streak or the at-risk flag. Production is live and `release_week_start` is NULL, so nothing may become member-visible yet.

**Approach:** One migration re-creates the two Epic 27 check-in paths with one added statement each (the dirty mark), adds the hourly `engagement_settle` job (a procedure with a commit per member), `private.engagement_state_view`, and the member pair `my_engagement()` (read) and `open_engagement()` (settles). Mobile gets a typed service. The acceptance criteria of `epics.md` "Story 30.3" are the authority; this spec adds the code map, the decisions below and the edge cases. No screen.

## Boundaries & Constraints

**Always:**
- One migration `0186_engagement_settle_triggers_state_view.sql` (0185 is the head, local only; numbers are assigned at merge time) with `scripts/rollback-0186-*.sql` (restores the 0178 bodies, unschedules the job, drops the new objects), `set local lock_timeout = '5s'` and a closing `do $verify$`. Every new function: `revoke execute ... from public, anon, authenticated` in the same file (`check:migrations`); the two public ones then `grant execute ... to authenticated` and `revoke ... from service_role`.
- The two amended bodies are generated by script from `0178_single_use_check_in.sql` (`private.record_check_in` lines 150-433, `public.void_staff_check_in` lines 440-614) with exactly one statement inserted each, and the verification step shows `diff` of each against 0178 is that one statement. The mark is the AC's upsert on `engagement_state(member_id, gym_id, dirty_from)`, placed right after the attendance insert (check-in, `event.visit_day`) and right after the void `update` (void, `ae.visit_day`), with no exception handler. It runs for every check-in and void regardless of `release_week_start`. Their `revoke` lines are restated. Existing check-in and void pgTAP files pass **unedited**.
- Job: `private.engagement_settle_job()` is a PROCEDURE, SECURITY INVOKER, no `SET` clause (either would forbid COMMIT; prove locally that it commits per member when run by `CALL`), every name schema-qualified. Scheduled with `cron.schedule('engagement_settle', '5 * * * *', 'call private.engagement_settle_job();')`. Candidates, in keyset batches of 200 ordered by member id: role `member`, `deactivated_at is null`, gym `status = 'active'`, epoch set, and either `dirty_from is not null` or (a counted visit day exists in a week that has already closed, i.e. the Monday of the member's earliest visit day is on or before the gym's last closed Monday, and `settled_through` is null or before the gym's last closed Monday `week_start_of(gym_today) - 7`, and that Monday is not before the epoch). A NULL `settled_through` counts as "before" so members with only pre-release history are picked up. Per member: `select ... from members ... for no key update skip locked`, settle with the gym's `gym_today`, caught errors, `commit`. One `job_runs` row per run (`started_at` = `clock_timestamp()` at start, `error` = `<n> of <total> members failed; first: <message>` on failure, status `failure`, else `success`). Epoch NULL: logs `success`, touches no member.
- The view: `private.engagement_state_view_at(p_member_id, p_now)` holds the logic; `private.engagement_state_view(p_member_id)` is `..._at(member, now())`; `private.open_engagement_at(p_member_id, p_now)` is settle at that day then the view; `public.my_engagement()` and `public.open_engagement()` resolve the caller live (role `member`, own non-deactivated member row, active gym, as `my_weekly_goal`/`set_weekly_goal` do, role check before the suspension check) and wrap the `..._at(..., now())` forms. Tests use the `_at` forms to move the clock; a test pins the wrapper to the same row at `now()`. The three functions return the same column list (a test compares `pg_get_function_result`), exactly the AC list in that order. `my_engagement()` is STABLE and returns no row for a caller who is not a live member of an active gym; `open_engagement()` is VOLATILE and raises `42501` for the same callers. Neither takes a member id.
- Semantics fixed here: `week_end` is the Sunday (`week_start + 6`); `in_release_week` is `epoch is not null and week_start < epoch` (the epoch Monday is a counted week); `visits_needed` is `greatest(goal - visits_this_week, 0)`; `goal_is_default` is "no `member_weekly_goals` row of any date"; `pending_*` is the earliest row after `week_start`; `daily_run` NULL, `shields_held` 0, `comeback_state` 'none', `at_risk_daily` false, `pending_milestone` NULL are literals; `needs_settle` is false when the epoch is NULL, true when `dirty_from` is not null, else the candidate rule above for that member. At-risk (weekly) needs a latest subscription whose status is present and not `expired` (no plan behaves as expired, as check-in treats it); every other plan, Pay-per-session included, is treated alike. Both flags are false when the epoch is NULL or `in_release_week`.
- GATES REACH THEIR CONSUMERS: the 30.2 function scan (`engagement_settle.test.sql`) becomes a pinned list that now includes the two check-in functions, the job, the view family and the public pair, with the "not executable by a client" assertion naming `void_staff_check_in` and `open_engagement` as the only authenticated ones. A new scan fails when any function that inserts into `attendance_events` or sets `voided_at` on it does not also write `engagement_state`.
- Close the 30.2 deferral: the stand-in mark leaves `scripts/engagement-race.sh` (the real `record_check_in` marks; header updated). `engagement_settle` and `engagement_determinism` keep direct marks because their fixtures are fixed March 2026 dates the real clock cannot reach; their headers say so and point to the real-path proof.
- Owner decisions carried from 30.1/30.2: one-line additions to existing pinned lists are allowed where a pin trips (expected: `support_request_path` callers of `current_gym_status()`, `engagement_facts` 'no public function' scan, the 30.2 scan above, `job-runs-alert.sql` expected list with a 150-minute gap and its `.test.sh`), `packages/types/src/database.ts` spliced by hand. No other edit to an existing test. Fixtures use Africa/Douala, fixed dates, never the clock. Mutation checks, run once and said so: remove the void mark and the check-in mark (each fails a named case); drop `skip locked` or take the member lock after the read (the race or a lock case fails). Restore all. Run `bash scripts/ci-local.selftest.sh` if `scripts/ci-local.sh` is edited.

**Never:**

## Design Notes

- `_at` forms exist only so tests can move the clock; the public functions are the single call sites with `now()`.
- A lost dirty mark leaves a week missed for good, so the mark is unguarded; the job's per-member `begin ... exception ... end` sits before the `commit`, never around it (a COMMIT inside an exception block is refused).

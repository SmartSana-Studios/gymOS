# Epic 2 Retrospective: Member Onboarding & Management

**Date:** 2026-07-18
**Participants:** Amelia (Developer, facilitating), Winston (Architect), Sally (UX Designer), John (PM), smartsana (Project Lead)
**Status:** First retrospective for this project — no Epic 1 retro was run, so there is no prior action-item follow-through to reconcile.

## Epic 2 Summary

Delivered all 8 stories (2.1 SMS/OTP Provider Sandbox Spike → 2.8 Member Self-Service Profile Management), covering plan configuration, member CRUD, CSV import, invitation, and the full member-app onboarding sequence (phone/OTP → profile → goal/experience → plan confirmation → self-service profile).

- Completion: 8/8 stories done.
- Review rigor: every story went through at least one code-review round; 2.2, 2.3, and 2.7 needed a second round because the first pass missed something real — two of those (2.2, 2.3) were genuine security-relevant RLS/constraint gaps.
- Zero production incidents (pre-pilot, nothing live yet).
- `deferred-work.md` picked up roughly a dozen new entries across the epic, ranging from accepted pilot-scale trade-offs to real open gaps.

## What Went Well

- **Strong reuse discipline across the epic**: `provisionMemberRow` extracted from `members.ts` and reused by `csvImport.ts`; `DeactivateMemberDialog` as the structural template for `InviteMemberModal`; `apps/dashboard`'s `LanguageToggle.tsx` optimistic-update pattern ported directly into the mobile profile screen (2.8). Very little was reinvented.
- **Hands-on verification repeatedly caught bugs static checks couldn't**: Story 2.1's live spike found six real integration bugs; Story 2.3's actual browser click-through caught a client/server import-boundary bug invisible to `tsc`/`eslint`; Story 2.7's `isOnboarded` navigation-gate bug was only found by tracing the real auth-state race, not the diff.
- **Review triage stayed disciplined for all 8 stories** — every finding categorized Patch/Defer/Dismiss with a stated reason, including the two rounds that caught real security bugs the first pass missed.

## Challenges

- **No physical device testing across three consecutive mobile stories** (2.6, 2.7, 2.8). Each one's Completion Notes honestly logged the same gap — verification has been `tsc` + RPC calls + manual comparison against mockups only, never a real tap-through.
- **Local Supabase/Docker reachability was inconsistent session-to-session** early in the epic (blocked 2.1/2.2, resolved by 2.3 onward via WSL) — already addressed going forward (this project now standardizes on running Supabase from WSL).
- **The same cross-field bug shipped twice**: the `grace_period` expiry-date direction was wrong in both `createMemberSchema` (2.3) and its mirrored `csvMemberRowSchema` (2.4) before being caught and fixed identically in both, same day.
- **Story 2.5 had an empty Dev Agent Record and unchecked tasks despite a working implementation already in the diff** — a bookkeeping gap, only caught because code review happened to notice the mismatch.
- **Two RLS role-gating bugs reached a second review round before being caught** (2.2's ungated SELECT — ruled intentional there; 2.3's ungated SELECT — a real PII-exposure bug). First-pass review is not reliably catching "which roles can hit this policy" as a class.
- **Two mobile navigation/auth-gate bugs shipped and were fixed within the epic** (2.6's new-member routing race, 2.7's stale `isOnboarded` gate + `router.replace` back-button breakage) — exactly the class of bug only a real tap-through surfaces early.

## Decisions Made This Session

1. **Physical-device testing is now a blocker, not a deferred item.** A real Android-device (or Expo Go) walkthrough of the full Epic 2 mobile flow (2.6 → 2.8: language → phone/OTP → profile setup → goal/experience → plan confirmation → self-service profile) must happen before Story 3.1 starts. Rationale: Epic 3's Story 3.4 (QR check-in) is fundamentally camera-hardware-dependent and can't be meaningfully verified without a device anyway — better to close the existing gap now than compound it.
2. **Add an explicit RLS role-gate checklist as a standing review step.** For every new/changed RLS policy, explicitly enumerate which roles can hit it and confirm that's intentional, before a first-round review is considered closed. Rationale: two role-gating bugs reached round 2 in one epic; Epic 3 adds new RLS surface (cron-driven subscription writes, QR/check-in tables) where the same class of bug is easy to reintroduce.
3. **Epic 2 is confirmed stakeholder-accepted** — no pending feedback that could force rework into Epic 3. Safe to build on as-is.
4. **No significant discovery requiring an Epic 3 plan update.** Nothing in Epic 2 invalidated Epic 3's assumptions (subscriptions.expiry_date exists and is populated correctly for the lifecycle cron; gym_token/QR is genuinely Story 3.3's job, not something Epic 2 was supposed to have built).

## Epic 3 Preview: Subscription Lifecycle & Attendance

Heaviest mobile epic yet: a nightly `pg_cron` job (first one in this project — no precedent in Epic 1/2), QR-code check-in with camera hardware, and four more member-app screens (Home, Check-In result states, offline queueing, Plan Details/History). It builds directly on Epic 2's `subscriptions`/RLS work and the mobile app shell.

## Action Items / Critical Path Before Story 3.1

1. **[Critical] ✅ Done (2026-07-18, same session).** Physical-device walkthrough of the full 2.6→2.8 mobile flow completed on a real Android device. Onboarding (2.6, 2.7) verified clean end-to-end including a real Twilio-delivered OTP. Found and fixed one real bug invisible to `tsc`/lint/two review rounds: Story 2.8's photo upload silently corrupted the file on Android (`fetch(uri)` unreliable against local picker URIs) — fixed via `expo-file-system`'s `File.arrayBuffer()`, which also fixed the identical latent bug in Story 2.6's onboarding photo upload. Recorded in `docs/decisions.md` (2026-07-18 entry) and the Story 2.8 file's own Change Log. No longer blocks Story 3.1 kickoff.
2. **[Critical]** Document the RLS role-gate checklist as a standing convention (e.g. a short addition to `architecture.md` or the code-review process) before Story 3.1's cron/RLS work begins, so it's actually applied, not just agreed to in a retro.
3. **[Prep]** `pg_cron` is new to this project — no existing spike or precedent. Given this project's established pattern of running a dedicated spike before a new integration (Stories 1.2, 2.1), consider whether Story 3.1 needs its own scheduling/timezone verification pass (nightly job at 02:00 Africa/Douala) before relying on it for the lifecycle state machine.
4. **[Tech debt, natural fit for 3.1]** `subscriptions` has no `CHECK (expiry_date > start_date)` — open since Story 1.3, still unresolved through Epic 2. Story 3.1 (the subscription lifecycle state machine) is the natural owner to finally close this.
5. **[Tech debt, carried forward]** `users.phone` still has no `UNIQUE` constraint at the DB level (relies on `auth.users.phone`'s GoTrue-level uniqueness) — flagged since Epic 1, not blocking, but now carried across two epics without resolution.
6. **[Housekeeping]** Working tree currently has uncommitted Story 2.8 changes (`profile.tsx`, `photo-upload.ts`, tab/locale updates) — commit before starting Epic 3 so the baseline is clean.

All patched pre-merge.

## Challenges

1. **Stories 6.4 and 7.1 were implemented, reviewed, and marked `Status: done` in their story files — but never committed to git.** They sat uncommitted in the working tree while Story 7.2 was committed on top of them. This surfaced only when preparing to merge, at which point the working tree held 200+ uncommitted changes across three unrelated concerns (two finished stories plus an unrelated BMad framework reinstall). "Done" in the story file did not mean "committed" — those became two different, silently-diverging facts.
2. **Reconstructing the missed commits introduced a smaller version of the same class of error.** While splitting the uncommitted diff by story, `supabase/tests/payment_notifications.test.sql`'s Story 7.1 test additions (the `plan(51)` → `plan(53)` bump and 2 new audit-shape assertions) were initially misfiled into the "Story 6.2/6.3 review fixes" commit based on a surface-level assumption about which bucket the file belonged to, rather than checking the story's own Task list. Caught and corrected (local history rewritten before anything was pushed), but only after the fact.
3. **A ~190-file BMad framework reinstall sat mixed into the same uncommitted working tree** as real feature code for an extended period, making `git status` hard to reason about and increasing the risk of exactly the kind of misattribution in #2.
4. **No automated test coverage for the Owner-only CSV export authorization gate** (Story 7.2, AC #4) — verified manually only, because no test runner (Vitest/Jest) exists anywhere in this repository. This is not a new problem, but it is now a recurring one: the same "no test runner" deferral has appeared in at least five stories (3.4, 3.10, 4.8, 6.4, 7.2).

## Key Insights / Lessons

- **Commit on "done," not on "next story started."** The gap between a story file reaching `Status: done` and the corresponding code actually being committed is where real work goes untracked. Treat "done" as the trigger to commit immediately.
- **When reconstructing a mixed diff after the fact, verify file-by-file against the story's own Task List / File List section** — don't infer a file's owning commit from its path or from which bucket "feels" right.
- **Framework/tooling upgrades deserve their own commit, immediately**, not left to accumulate alongside feature work.
- **The "no test runner" deferral has stopped being a one-off exception and become a pattern.** It's due an explicit decision rather than continuing to silently re-defer in each new story's review.

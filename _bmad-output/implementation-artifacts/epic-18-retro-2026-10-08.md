# Epic 18 Retrospective — Registration Fee

Gyms charge a flat one-time registration fee; in a fee gym a new member is "awaiting" (no app access, no plan) until staff collect the fee (cash, transfer, manual MoMo, Tara Money) or an Owner/Supervisor/Manager waives it; a mistaken manual fee can be voided; the fee has its own revenue line; existing members are never charged. Source of intent: `_bmad-output/implementation-artifacts/epic-18-context.md`, `_bmad-output/planning-artifacts/epics.md` (FR-147..FR-155), `spec-18-1` … `spec-18-7`.

## Findings

Each finding: source — disposition (what to do about this instance) — prevention (what stops the next one).

### Spec-to-implementation reconciliation

- **S-1 Assign-plan role reversed.** Spec 18.6 / `docs/decisions.md` (2026-10-07 dashboard fee surfaces) fixed "Assign plan: Manager-plus" and the RLS INSERT policies allowed manager/supervisor/owner only. Manual QA found receptionists could not register members or assign a first plan. `0102_receptionist_create_members_assign_plans.sql` widened the two INSERT policies; `MembersPageClient.tsx` `CAN_CREATE`. — *Accept* (product decision recorded in decisions.md 2026-10-07 "Receptionists can register…"); **reconcile spec 18.6 and `epic-18-context.md`** (action 9). — Prevention: role matrices in a story spec need a business-owner confirmation step, not only RLS archaeology.
- **S-2 Invite timing.** Epic context said "WhatsApp invite is sent only once the fee is settled" (a gate, not a trigger). As built after release: manual button (18.5) then automatic after settlement (`MembersPageClient.tsx` `sendAutoInvite`, `525f2d9`) and automatic at creation in a fee-0 gym (`actions.ts` `createMember`, `0968039`). — *Accept*, reconcile spec text (action 9). Known gap: Tara payment settled by webhook while no dashboard is open sends no invite (action 8).
- **S-3 Deferred release-sequencing item resolved.** `deferred-work.md` ~l.911 ("do not deploy 18.1 ahead of 18.2") — honored: stories stayed local until all seven were done, then deployed together. — *Accept*.
- **S-4 Existing members show no fee line.** Fee line hidden for state `none` (`MemberModal.tsx` ~l.605); a grandfathered member in a fee gym shows nothing, which the pilot user read as "missing". — *Defer* (product decision, action 10).

### Pattern divergence

- **P-1 Hosted-vs-local privilege drift (highest-impact finding).** All migrations `revoke … from public` (and sometimes `authenticated`); the hosted project's default privileges also grant EXECUTE to `anon`, so on production 70 functions were callable without a session, including SECURITY DEFINER getters returning a gym's decrypted Tara API key and webhook secret and `complete_verified_payment` / `complete_flagged_payment` (found when `0100`'s own verify failed during deploy). Pre-existing, not introduced by Epic 18. Fixed by `0100` (`revoke … from anon`) and `0104_align_function_privileges.sql`; written up in `docs/decisions.md` 2026-10-08. Local pgTAP and manual QA could never see it because the local stack has no such default. — *Fixed now*; **prevention:** a hosted-parity ACL check before every production deploy and a pgTAP/CI guard that no new `public` function is anon-callable unless allow-listed; decide on `alter default privileges … revoke execute from anon` (actions 2, 3).
- **P-2 Live provider behavior differed from the docs and the 2026-07-31 spike.** Four defects only a real Tara run exposed: secret header spelled `tara_webhook_secret` not `tara-webhook-secret` (`TaraMoneyProvider.ts` ~l.452, `c218fb6`), cancel arrives as `status:"ERROR"` not `FAILURE` (`e9f47e8`), callback URL must be https while the function saw an internal http origin (`_shared/callbackUrl.ts`, `f8a4444`), and Tara's `/resend-webhook` delivers **no** secret header (unresolved, action 6). Source: the spec itself flagged "18.3 needs sandbox verification" (`epic-18-context.md`) and `deferred-work.md` ~l.931 ("no test exercises the webhook with `purpose = 'registration_fee'`"). — *Fixed now* (three) / *Open* (resend). Prevention: a story that depends on an external provider's live behavior is not `done` until a real sandbox/live round trip is recorded, and real payload fixtures are saved into the Deno tests.
- **P-3 Bookkeeping drift made tooling unusable.** 112 non-comment `last_updated:` keys in `sprint-status.yaml` broke `sprint_status.py`; the file is also a decisions log. — *Fixed now* in this run (converted to comments). Prevention: append bookkeeping as `# last_updated:` only, and validate the file with the skill's parser at story close (action 12).
- **P-4 Production-touching CLI constraints.** `supabase functions serve`/`db push` and host `psql` are unusable here; the release needed bespoke tooling (`scripts/prod-db.sh`, `scripts/epic18-qa/start-edge-functions.sh`, `scripts/deploy-0098-0103.sh`, backup script). — *Accept*; keep the scripts, they were rehearsed on the local DB.

## Behavior verification

Exercised end to end (local stack + a live Tara business account through a tunnel, then production):

- Collect by cash/transfer; waive with reason; void of a manual fee; void of a Tara fee refused ("corrected outside GymOS"); refund of a fee payment blocked; revenue line; receptionist create-member / assign-plan; pagination; staff role limits — owner QA pass on the local stack.
- **Tara, real 50 XAF payments:** success → member settled, `mobile_money`/`taramoney`, provider fee 2, no subscription, no notification, audit `registration_fee_paid`. Cancel (webhook with `ERROR`) → payment `flagged`, then cash collection succeeded. Dismissed prompt (no webhook) → request stayed `processing` until the 10-minute lazy expiry on next dialog open, then `flagged`, then cash worked. Collect/Waive refused while a request was open. A re-sent webhook for a settled payment → acknowledged as duplicate. Status-endpoint check: confirmed path silent, unknown transaction → "inconclusive, completing on the webhook" (live Tara answer `ERROR / TRANSACTION_NOT_FOUND`).
- **Production deploy:** preflight read-only checks passed (head 0097, 1 gym / 2 members / 0 payments); backup taken; 0098/0099 applied; 0100 stopped at its own verify (P-1); 0100–0104 applied after the fix; verification: awaiting 0, fee-gym 0, 5 fee RPCs, 5 triggers, anon cannot read gym credentials or complete payments, the 12 anon-callable functions equal the local set. Function redeployed and answers. Vercel deployments for owner/portal served after the push.
- **Not exercised:** the fee flow on a physical phone with the new build; a real Tara cancel webhook; the Android and iOS stores' processing results; any production traffic beyond the pilot gym's first use.

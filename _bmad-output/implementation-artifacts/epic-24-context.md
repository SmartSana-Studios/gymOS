# Epic 24 Context: Gym Landing Pages

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

A gym can publish one optional public page at `{name}.gymosapps.com`, rendered by a swappable template over the gym's own content. Nothing is public until the Owner acts: existing gyms start with no page, no name and no public plan. The public site reads only a published projection through one hardened read-only role, never tenant tables, so a defect there cannot expose a member, a payment or a staff identity.

## Requirements & Constraints

- One optional page per gym; no login, member counts or staff names on it; visitor can call, open WhatsApp or get directions. Public contact is separate from the Owner's login phone, which is never written to page fields or shown.
- Owner, Supervisor and assigned support edit and publish; only the Owner (or Super Admin) claims or renames the name.
- Publish gate (re-evaluated on every change; a page that stops meeting it unpublishes itself and the Owner is told why): name, category, logo, banner, About of at least 100 characters in at least one language, country and city, one public contact, opening hours, one public plan. Plan visibility is opt-in, private by default.
- Name grammar: 3 to 30 chars of `a-z0-9-`, no leading/trailing hyphen, no `--`, no `xn--`, not digits only; unique case-insensitively; reserved list; first come first served; reserved to the gym while unpublished or suspended up to 12 months; at most two renames per rolling 12 months; old name 301s (one hop) for 12 months.
- Super Admin takedown with reason code blocks republishing; public report form answered within 5 business days; Owner appeal path (built in 24.11).
- Text only: no HTML or script from a gym reaches the page. Images are re-encoded with metadata stripped, bounded (4 MiB upload cap), served from a separate cookieless origin, purged on unpublish or delete.
- An unpublished, taken-down or suspended page returns one identical not-found response and leaves address, directory and sitemap within 60 s at the origin, CDN purge within 5 min, sitemap within 15 min.
- Language (OQ-28, updated 2026-11-08): content languages are an open list (today EN and FR), each optional; a language is offered only when its required language-bound fields are complete (today About of 100 chars or more); at least one complete language is needed to publish. Plan names are never translated; type, interval and duration are translated by the template. Page chrome EN and FR. Build editor, language link and completeness check from one supported-languages list, not hard-coded EN/FR pairs. This supersedes the older fixed-chrome, no-hreflang wording.
- NFR: p75 LCP 3 s on mid-range Android over 4G (baseline measured in 24.12: 3.5 s lab, local; the 3 s stays an assumption until a staging number); security headers per the CSP/HSTS design; published column list pinned by snapshot test.

## Technical Decisions

- `public_site` schema holds views only; one login role `public_site_reader` reached through the pooler from server code. `apps/landing` holds no Supabase client, anon key, service-role key or JWT secret (CI check exists). Sole exception: `submit_page_report()`.
- Tenant identity comes from the Host header alone. Nameservers stay at A2 Hosting; `NS _acme-challenge` is delegated to Vercel and `CNAME *` points at `apps/landing`; explicit records for owner., portal., www., apex and mail win over the wildcard.
- Staff auth cookies are host-only with the `__Host-` prefix (built in 24.3, shared `cookieOptions`). Gym pages are static server-rendered HTML, no client JavaScript, strict CSP (`script-src 'none'`, per-page style hash, media-origin images only, `frame-ancestors 'none'`), no cookies set.
- Page names are rows with one grammar and one reserved source. `gym_pages` holds the snapshot built by the database; every source change re-snapshots or unpublishes (AD-46); freshness is a TTL (`s-maxage=60`), not a purge. Templates are pure modules (`render(content, locale)` only export, no DB or network import) over versioned, strictly validated content (`PageContentV1`, `.strict()`), failing closed to not-found.
- Built in 24.10 (migration 0166, not applied to production): `packages/page-templates` (contract, registry with Classic only, render pipeline, conformance suite with DOM rules and a Chromium layout stage, known-bad fixtures), `apps/landing` proxy host routing, `app/gym-site/route.ts`, the `pg` reader (`lib/gym-site/db.ts`), the uniform not-found, self-hosted Barlow, `PageContentV1` in `packages/types`, `public_site.page_redirects`, `default_language` in the snapshot. ## UX & Interaction Patterns

Screens for 24.9 (Settings gains a "Landing page" row: status badge plus [Open], like Staff; no sidebar entry). Absent controls are removed from the DOM, not disabled. Manager, Receptionist and Coach never see the row.

**Editor, `/settings/landing-page`** (own page, own [Save changes], toast "Page saved."):
- Header: status badge and [Review & publish]. Statuses: Not started, In progress (button disabled, missing items listed), Ready, Published ([Unpublish]), Offline gate failed, Offline gym suspended (page hidden, copy kept), Offline name released ([Claim a name] for Owner), Taken down ([Appeal], Owner only). Always badge plus label plus icon.
- Checklist of nine required items (name, category, logo, banner, About in one language, country and city, public contact, hours, one public plan) plus optional gallery, services, map position. Each missing item links to its field. Information line "Languages offered" lists complete languages and what an incomplete one lacks (for example "needs 32 more characters in About"); it is not a tenth item and does not block. Checklist and publish list render from one server function; client only maps codes to labels and anchors; refresh after save and on focus, only the About counter is local.
- Sections: Page name (Owner: [Claim a name]/[Change name]; others read-only text "Only the Owner can change the page name."; states Not claimed, Under review, active), Page text, Images, Location, Opening hours, Public contact, Plans on your page, Template.
- Page text: one section with language tabs for About and Services (each up to 2,000 chars, per-field counters). Tabs shown only for the default language and languages with saved text; [+ Add language] ("Add French") adds a tab, a menu from three languages; each tab shows status (Complete, needs N more characters, Empty) as icon plus words; from five tabs it becomes a dropdown. One form, one Save; typed text survives tab switches. Non-default tabs have [Remove French text] with a destructive confirm (warns if it would take a live page offline). Errors on another tab mark "Needs attention"; on refused save select the first such tab and focus the field. `role=tablist` roving tabindex, arrows/Home/End. Services: one per line. Text only; `<` and `>` rejected inline; errors name the field and language.
- Location: country, city, address, optional map position (both lat and lng or neither). Hours: one range per day in gym timezone with [Copy Monday to all days]. Public contact: phone and WhatsApp in E.164, at least one. Category read-only with link to Settings.
- Plans: every plan listed read-only with its own currency, one "Show on my page" switch each, default off; no label fields. Switching off the last public plan on a live page warns the page will go offline.
- Images: shared uploader for logo, banner, gallery (up to 12); JPEG/WebP/PNG, up to 4 MiB (UX text says 5 MB, owner chose 4 MiB); attestation checkbox before upload; logo comes from Branding.
- Template picker: launch ships one card, "Classic" ("More templates are coming"); the swap must never re-ask for content. Selection lists only templates that passed the conformance suite. Preview is undecided.
- Live page: persistent info line "Saved changes can take up to 2 minutes to appear"; no separate draft. A save that would break the gate warns first, naming the failing item. Too-large content shows a banner. First Settings visit after release shows a prompt [Set up my page]/[Not now] (dismissal remembered per user); nothing is published either way.
- Auto-unpublish banner (also on the publish screen): one EN/FR sentence per gate code plus `name_released`, with a way out and anchor links; several codes show a bulleted list in checklist order. Taken-down banner shows the reason label and Appeal (500-char reason modal).

**Publish, `/settings/landing-page/publish`**:
- States the public address, then lists exactly what becomes public, generated from the same field list the server publishes: name, category, logo/banner thumbnails, Languages offered, About and Services one row per supported language ("Not included" for an incomplete one), plans with name as entered and translated details and own currency, address, hours, public contact (shown in full here only), gallery count, colour swatch. Then "Never shown: member names or counts, staff names, your sign-in phone, payments, private plans."
- One attestation checkbox for all images; [Publish page] disabled until ticked. Server re-validates; on failure it lists what is missing with the same anchors and publishes nothing; a taken-down page returns `taken_down` and shows no Publish button. Success: live address, [Copy link], [View page], focus to the success region, "up to 2 minutes" note.
- Unpublish confirm modal (always allowed): visitors see "This page isn't available", the name stays reserved.

**Public page and templates (for 24.10, shared constraints)**: ten fixed sections in fixed order; contact actions (Call, WhatsApp, Directions, at least 44 px tall) inside the first screen at 360x640, 768x1024 and 1366x768; three CSS-only breakpoints (under 641, 641 to 1023, 1024 and up) with identical DOM order, banner with an overlapping header card, desktop contact card with the phone number as visible text; omit, never empty; no "open now"; gym `primary_color` is the only variable colour with a server-computed `--on-gym` text colour (AA contrast); Barlow 700/800 self-hosted plus system sans; one inline hashed style block; language link/menu and `hreflang` only for complete languages; uniform not-found for every non-visible cause. Classic is a light card design (page `#F3F4F0`, white cards, gym colour only on the Call tile, logo ring, map pin and focus). Seed A dark and seed B light mocks live in `mockups/`; if a mock and the spine disagree, the spine wins. Resolved 2026-11-09 (owner): 24.10 ships Classic only; seeds A and B are deferred library growth.

All Owner-facing copy EN and FR through the existing i18n layer; use "page" for the public web page, "unpublish" (not delete or remove), "public" (not live) for plans.

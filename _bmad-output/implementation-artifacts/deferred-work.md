## Deferred from: code review of story-1-10-bilingual-en-fr-platform-foundation, i18n infra pass (2026-07-10)

- The ESLint `i18next/no-literal-string` gate's default `mode: "jsx-text-only"` never checks JSX attribute values (`aria-label`, `alt`, `title`, etc.) — the `jsx-attributes` config block this story added is currently dead configuration [apps/dashboard/eslint.config.mjs, apps/super-admin/eslint.config.mjs] — switching to `mode: "jsx-only"` closes the gap but also starts checking every string literal anywhere inside a JSX subtree, surfacing ~130 false positives (CSS variant/size enums, htmlFor refs, state-machine action strings, fallback display chars) across both apps that need a dedicated `callees`/`object-properties` exclude-list tuning pass to resolve properly. The specific hardcoded strings found during this review were fixed directly; the gate itself doesn't yet prevent new regressions in this category.

- ESLint's inherited `words.exclude: ["[A-Z_-]+", ...]` whitelists any all-caps-only literal, which could hide a real untranslated UI string — this is the plugin's own upstream default, not introduced by this story; changing it is a broader linting-policy call.
- `apps/super-admin/eslint.config.mjs`'s dead-code `{ ignores }` block (11 Supabase-starter scaffold files) relies on a one-time grep verification with no automated re-check if any of those files becomes reachable again.
- Locale strings paired with dynamic counts (`gracePeriodUnit`, `capacityUnit`, `alertAutoDismissUnit`) have no i18next plural (`_one`/`_other`) suffixes, so e.g. a grace period of 1 renders "1 days" — fixing properly touches multiple already-shipped component call sites; better as a dedicated pluralization pass across the whole app.
- No super-admin-scoped RLS UPDATE policy exists on `users` for phone changes [supabase/migrations/0015_users_self_service_language_preference.sql] — FR-023's "phone changes require admin intervention" has no built admin-side path yet; belongs with a future user/admin-management story.
- `client-provider.tsx`'s `locale` prop isn't re-applied via `changeLanguage` if it changes after mount — narrow edge case; the only real language-change flow (`LanguageToggle`) already calls `i18n.changeLanguage()` directly and imperatively.
- `check-i18n-key-parity.mjs` throws a raw unhandled error (stack trace) on missing/malformed locale JSON instead of a clean CI-friendly message — still fails the build correctly, just with a less polished error.

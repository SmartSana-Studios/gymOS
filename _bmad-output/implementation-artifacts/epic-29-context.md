# Epic 29 Context: Classes — A Different Time Each Day, and Coach Access

<!-- Compiled from planning artifacts. Edit freely. Regenerate if planning docs change. Source of truth for acceptance criteria: epics.md "Epic 29 — Stories" (Stories 29.1–29.4). -->

## Goal

A recurring class gets its own time on each weekday (stored as rows, up to 14 per class), a Coach creates, edits and cancels their own classes from My Classes, and Owner, Supervisor and Manager view any coach's classes, rosters, assigned members, session notes and workout plans through a read-only coach picker that can never reach body or progress data. Production is live with real gyms, real classes and real bookings: this epic rewrites the daily session job, expands every existing recurring class, widens who may write `classes`, and adds the only staff read path onto coach data. Existing sessions, bookings and screens must come through unchanged, and the existing pgTAP suites pass without fixture edits except where a story names the test that changes. The epic is independent of Epics 27 and 28.

## Stories

- Story 29.1: Class Schedule Slots Foundation (No UI Change)
- Story 29.2: Per-Day Slot Editor and Cancel Class
- Story 29.3: Coaches Create, Edit and Cancel Their Own Classes
- Story 29.4: Coach Picker for Owner, Supervisor and Manager

Chain 29.1 → 29.2 → 29.3 → 29.4. The server half of 29.4 (read functions, isolation CI check) needs only 29.1 and 29.2; its Classes tab reuses 29.3's My Classes list component. All merge to `epic/29` and reach master together.

## Requirements & Constraints

- A class can have different times on different days; the same weekday may appear twice at different times; at most 14 weekly times per class (stable refusal on the 15th, race-safe); identical weekday and time refused. Booking stays per session; capacity and booking rules are unchanged.
- Migration of existing recurring classes must be exact: one slot per selected day at the class's single time, and `class_sessions` and `class_bookings` byte-identical before and after (the migration self-verifies and rolls back otherwise). One-off classes get no slot.
- Slot edit rule (recurring classes only): future sessions with no bookings that no longer match are deleted and new ones generated; a booked session that no longer matches is kept untouched and returned to the editor as "left unchanged"; past sessions are never touched; repeating an edit is idempotent. One-off classes keep today's refusal to reschedule over bookings.
- Cancelling a class flags it and its future sessions (never deletes, bookings and attendance stay); a cancelled class is excluded from the daily job, from booking, attendance marking, member cancellation, the class reminder and the bookable list. No push, SMS or in-app notification on cancel (owner decision 2026-11-15, recorded in `docs/decisions.md`). Cancel returns the server-computed count of bookings cancelled and audits it.
- A Coach may create, edit and cancel only classes where they are the coach, may not assign another coach or take over another coach's class, and still has no access to the admin Classes page, no roster writes and no attendance marking. Manager, Supervisor and Owner keep full control of every class in their gym.
- The picker is read-only, limited to the caller's own gym and to Owner, Supervisor and Manager; Receptionist, Coach, member, anon and GymOS Support get an empty result. It exposes classes, rosters, assigned-member profile (allow-listed columns only), the chosen coach's own session notes and authored workout plans. It never exposes measurements, weights, progress entries or photos, progress notes, plan completions, the Coach Overview progress feed, or the member's starting weight, height, birth data, email, emergency contact, neighbourhood or profession. Progress-table RLS is unchanged.
- NFR-001 (tenant isolation on every new table, view and function, cross-gym pgTAP per role; booking and session reads stay inside the page-load target, p95 under 2 s; picker lists stay under the 1000-row API cap with an index check), NFR-011 and NFR-016 (progress access untouched and re-verified per request).
- Every new `SECURITY DEFINER` function passes `scripts/claim-inventory.mjs` (no new `claim-only` entry), `suspension_rpc_coverage.test.sql` (a "gym is not active" guard, no comments in the body) and the support-capabilities catalog test. None of this epic's functions is a support capability, so the pinned totals and names in `support_capabilities.test.sql` stay unchanged (29.2 extends the catalog test's classification of functions that mention `'supervisor'`).
- Each migration ships with a rollback script and regenerated `packages/types/src/database.ts`; full `scripts/ci-local.sh` green per story; `scripts/check-migration-guardrails.mjs` passes. Migration numbers are assigned at merge time; earlier stories never renumber.

## Technical Decisions

- Data model (29.1): `class_schedule_slots(id, class_id, gym_id, weekday 0=Sunday..6, start_time minute-precision, created_at)`, unique `(class_id, weekday, start_time)`, index on `gym_id`. A before-insert/update trigger enforces same gym as the class and forbids moving a slot; the 14 cap trigger takes `FOR UPDATE` on the class row before counting. `recurrence_start_date` stays on `classes`; `recurrence_days` and `recurrence_time` stay (nullable for recurring rows) and are not dropped (clean-up migration deferred and recorded in `deferred-work.md`). `classes_schedule_matches_type` is replaced so recurring needs only the start date; a deferred constraint trigger refuses a recurring class with no slot and a one-off class with any.
- RLS (29.1): gym members read the gym's slots, a restrictive `tenant_active_gate` denies a suspended gym (0124 pattern); INSERT/UPDATE/DELETE are revoked from `authenticated`, `anon` and `service_role`; the definer functions are the only writers (0111 pattern).
- Materializer: `private.materialize_sessions_for_class` and the daily job `class_session_materializer` read slots, convert `start_time` with the gym's timezone at generation, insert `on conflict (class_id, scheduled_at) do nothing`, still log one `job_runs` row. The rolling window (`current_date .. +4 weeks`, server date) is deliberately unchanged; its imprecision goes in `deferred-work.md`. A later gym timezone change moves no existing session. Equivalence test against the old column-based output, including a DST zone and a Sunday slot.
- Single regeneration path: `private.apply_class_slots(class_id, slots jsonb)` (definer and service role only), returning the left-unchanged sessions. Lock order (AD-21): class row `FOR UPDATE` first, then candidate future sessions `FOR UPDATE` in `scheduled_at` order, then the no-booking re-check under the lock. Concurrency test of `book_class_session` against it (50 iterations, no deadlock, no orphaned booking, no FK error to the editor).
- API (29.2): `create_class(..., p_slots jsonb)` and `update_class(..., p_slots jsonb)` as new overloads (same parameters in the same order plus trailing `p_slots` with no default); old signatures stay for the rollout window (migration deploys before dashboard). `p_slots` is `[{weekday, start_time "HH:MM"}]`; stable messages for none, over 14, bad weekday or time, duplicate, seconds, slots on a one-off. `update_class` returns `{ left_unchanged: [{class_session_id, scheduled_at, booked_count, capacity}] }`. A per-day-times class stores null legacy columns. Create and update write audit rows for weekly-times changes.
- Cancel (29.2): `classes.cancelled_at`, `classes.cancelled_by` (members id, null unless cancelled), `class_sessions.cancelled_at`; `public.cancel_class(class_id)` definer, revoked from public and anon, role from `private.current_member_role()` live, gym from `private.gym_id()`, returns `{ bookings_cancelled }`, audit action `class_cancelled`. Already-cancelled gets its own stable message; other gym, missing and unauthorised share one uniform not-found. `list_bookable_class_sessions()` omits cancelled; `list_my_class_bookings()` adds `class_cancelled`.
- Old-time tag (29.2): `security_invoker` view `class_sessions_with_match` (`matches_slots` by comparing the session's local weekday and time to the slots; one-off always matches; plus `cancelled_at`) is the single source. `list_my_classes()` is dropped and re-created with `slots jsonb`, `cancelled_at`, per-session `matches_slots`, legacy recurrence columns removed from its output; `services/classes.ts` and `coach/classes/page.tsx` read slots.
- Coach grant (29.3): no Coach table write policy is added and Coach table writes stay refused; the grant is the three functions, gated by the live role (`private.current_member_role()`, never the claim, AD-34) plus the caller's own live member row (`user_id = auth.uid()`, gym, `role = 'coach'`, not deactivated) together with `private.is_own_coach_id` (which alone checks neither gym, role nor deactivation). Create: coach id must be the caller's own or null (stored as caller). Update and cancel: the old row's coach and any new `p_coach_id` must both be the caller's own. Another coach's, another gym's and a missing class give the same message (`classes.coach.ownOnly` surface). Reassignment by a Manager moves edit rights on the next request.
- Picker (29.4, AD-58): new `STABLE` definer functions with a `p_coach_id` parameter, `search_path = public, pg_temp`, revoked from public and anon, granted to authenticated: `list_coach_classes`, `list_coach_class_session_roster`, `list_coach_assigned_members`, `get_coach_assigned_member`, `list_coach_member_session_notes`, `get_coach_member_workout_plan`, `list_picker_coaches`. Each reads the live role (empty result, never a revealing error), raises "gym is not active" for a suspended gym, filters every table on `gym_id = private.gym_id()`, asserts first that the coach belongs to the gym with role coach (null-safe) and, for member-scoped functions, that the member is currently assigned to that coach (`coach_assignments.ended_at is null`). `RETURNS TABLE` with a named column allow-list only: never `select *`, a row type or `to_jsonb` of a row; no comments in the body.
- Isolation CI check: `scripts/check-coach-picker-isolation.mjs` plus pgTAP twin `coach_picker_isolation.test.sql`, wired into `scripts/ci-local.sh` and GitHub Actions. It finds picker functions by name pattern and by the committed allow-list `scripts/coach-picker-functions.json`, walks `pg_depend` transitively and fails on any path to the deny list (`progress_entries`, `progress_photos`, the progress-notes table, `workout_plan_completions`, the object behind the Coach Overview progress feed; real names verified in migrations at story time, and a comment says new body-data tables must be added). It self-tests with fixtures that reach a progress table two levels down, fails if a picker function is in `private.support_capabilities`, and fails on a stale allow-list entry. A positive seeded test scans every returned row of every picker function for seeded body values.
- Dashboard: the picker route issues no writes (a Supabase client double that throws on non-`rpc` reads and on RPCs outside the allow-list); the chosen coach is carried as `?coach=<id>`; for the Coach role the id is resolved server-side and any `?coach=` is ignored.

## UX & Interaction Patterns

- Classes page (UX screen AD-18): Schedule column shows recurring times grouped by identical hour, Monday first, 24-hour, gym time zone, three groups then "+N more" with a tooltip of the full list; migrated classes read as before ("Tue, Thu 18:00"). [Edit] and [Cancel class] for Manager and above, absent from the DOM for Receptionist; cancelled classes show a neutral "Cancelled" badge, sort below live ones, offer no actions; the "Old time" tag shows in the expanded row of a future booked session that no longer matches.
- Create/Edit modal (UX AD-19): weekly-times editor with one row per time (Day select, 24-hour Time, Remove), "+ Add a time" pre-filled from the last row, counter "n of 14" always visible (control stays visible and `aria-disabled` at 14), rows re-sorted Monday first on blur and save with a polite announcement, inline per-row errors plus a summary, edit notice above the list, no "migrated" label. On save of an edit the modal shows an in-place result view listing sessions left unchanged ("n / capacity booked"), with [Done] returning focus to the row's [Edit]; a create closes as today. Coach mode: Coach is plain text of the signed-in coach, not a select.
- Cancel class dialog: Escape disabled, buttons [Keep class] / [Cancel class], server count in the body, separate no-bookings copy, success toast.
- Coach My Classes (UX AD-21): [+ Create class], [Edit], [Cancel class] per own class; roster and attendance stay read-only (no mark control in the DOM); empty state with [+ Create class]; a stale-tab refusal shows `classes.coach.ownOnly` and refreshes. The Coach still gets the global permission message on `/classes` and no Classes sidebar item.
- Coach picker (UX AD-32 and picker-mode amendments of UX AD-14, AD-15, AD-20, AD-21): Coach Portal sidebar item for Owner, Supervisor and Manager, not Receptionist or Support; with nothing chosen only the select is shown and no coach data loads; select lists active coaches, pre-set when only one exists; neutral non-dismissible read-only banner; sub-navigation Classes (default) and Members only (no Overview); Overview or Progress addresses show one "part unavailable" message; member detail shows header, Session Notes and Workout Plan tabs only (Progress tab absent from the DOM, never locked or blurred), no count, chart, thumbnail or "no data yet" placeholder, and the persistent no-body-data line; unassigned member shows a "not assigned" state; no-coach, unavailable and inactive-coach states have their own copy.
- Member app (MA-16 and Home upcoming classes): cancelled bookings show a neutral "Cancelled" badge, Home drops them; this is not drafted in the UX contract, so reuse the shared badge style and add EN and FR mobile keys.
- Audit log (UX AD-12): new labels for weekly-times changed, class cancelled and class created by a coach (Coach as actor).
- All new strings in EN and FR (dashboard locales and mobile catalog, "Group F" and "Group G" keys); `scripts/check-i18n-key-parity.mjs` must pass. No mock-ups: design lives as text in the spec files.
